File-based Guestbook

Visitors post a message, it gets saved to a text file on the server, and every message ever posted shows up on the page — no database involved, just a file.

What this project is

Every project so far has been "one submission in, one result out" — nothing was ever remembered afterward. This is the first project where data survives.

◧

What is this

A form collects a name and a message. Instead of just showing a result and forgetting it, PHP writes it to a file on the server. Every time the page loads, PHP reads that file back and lists everything anyone has ever posted.

  • Write: append the new message to a text file
  • Read: load the whole file and list every past entry
  • No database, no setup — just a plain file living next to your PHP script
✦

Why it matters for a beginner

This is the project where your app stops being stateless — up to now, closing the browser meant everything was gone. That changes here.

  • First real taste of persistence — the core idea behind every database later
  • Forces you to think about data format: how do you store a "message," not just a number?
  • Introduces a genuinely new failure mode: what if the file doesn't exist yet, or isn't writable?
  • Directly prepares you for PDO/databases — same "write it, then read it back" shape, different storage

File I/O — 3 examples

The three functions that make this whole project possible. Everything else is just validation and looping, which you already know.

writing a file (overwrite)
file_put_contents(
    'notes.txt',
    'Hello!'
);
// creates the file if it
// doesn't exist yet, or
// replaces it entirely
// if it already does
The most basic write — but dangerous for a guestbook, since it erases everything already saved.
appending instead of overwriting
file_put_contents(
    'guestbook.txt',
    $line,
    FILE_APPEND
);
// FILE_APPEND adds this
// onto the END of the
// file, keeping every
// past message intact
This is the flag that actually makes a guestbook work — every new message joins the list instead of replacing it.
reading a file back, line by line
$lines = file(
    'guestbook.txt',
    FILE_IGNORE_NEW_LINES
);
// $lines is now an array
// one entry per line —
// ready for a foreach
file() (not file_get_contents()) reads a file straight into an array — perfect since each line is one message.

Build roadmap

Same approach as before — build in order, test after each step.

Static form shell

Two fields: name and message. Submit to self, same as always. Below the form, leave an empty spot where the message list will render.

Detect POST, validate both fields

Same shape as validateScore() — reject blank name or blank message. Decide a reasonable max length for the message so one visitor can't post a giant wall of text.

validation

Decide the storage format

Turn one entry into one line of text using json_encode(['name' => ..., 'message' => ..., 'time' => ...]). JSON-per-line avoids a real headache: if you used a plain separator like |, a message containing | would break your parsing later.

data format

Append the new entry to the file

file_put_contents('guestbook.txt', $jsonLine . "\n", FILE_APPEND) — the "\n" at the end matters, it's what keeps every entry on its own line.

file I/O

Guard the "file doesn't exist yet" case

Before reading, check file_exists('guestbook.txt'). On the very first visit ever, there's nothing to read — treat that as "zero messages," not an error.

edge case

Read every line back

file('guestbook.txt', FILE_IGNORE_NEW_LINES) gives you an array of raw JSON strings — one per past message, oldest first.

Decode each line back into data

Loop with foreach, running json_decode($line, true) on each one to turn it back into an associative array — the reverse of Step 3.
